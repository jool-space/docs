Tempest.Compiler.Implement

Tempest.Compiler.Implement — Module

The interface kernel packages implement. An implementation realizes groups of a plan as kernels: it claims the groups it can realize, estimates the launches of each claim, and builds them. It may also propose groups of its own. An implementation is a value, and a target holds those it uses (see CUDATarget). Claims read a GroupView of the group, in the vocabulary of Tempest.Compiler.IR.

source
Tempest.Compiler.Implement.Implementation — Type

An implementation realizes groups of a plan as kernels. claims returns the ways it can realize a group, estimate the launches of each, and build_claim builds them. A target's floor realizes any group, so a plan never depends on an implementation. claims, variants and estimate answer of their arguments alone, and the cover asks them for many groups side by side, on the threads there are: what they keep between calls, as a trial compilation or a library's graph, they keep in a table a lock guards.

Tempest.Compiler.Implement.GroupView — Type
GroupView

A group of the plan as implementations see it. A group computes its members over one domain: reductions, its folds, and outputs, its other values, each defined by its term in terms; a fold may cover fewer of the domain's positions (see own_domain). A :recurrence group's outputs are a recurrence's state, its term where the state starts; the values of its cycle it stores, in order; and last the value the state is carried from, the state one step on, stored only where something else reads it. Each step computes them in order, reading what it stored, over the axes their placements mention (see recurrence_axes). A :scan group's reductions are scans along its primary_axes in one direction, which its members read at the position its sweep has reached. Folds over primary_axes, the axes its first fold not by key reduces, can be read within the group, and phase counts the folds each member waits for. values describes every value the group computes or reads, placement where it keeps each member (its index over the domain, or nothing), and bytes what it reads from storage and writes. reference(target, buffers) builds the group's reference kernels, the floor's, which every claim agrees with. Its structure is the rest in its own numbering.

source
Tempest.Compiler.Implement.ValueView — Type

What a view holds of a value: its element type and dims, whether it is a number rather than an array (stored as one element), and whether it is stored; for a fold, the fold and the axes of its domain it reduces, and whether it is a fold by key (keyed), which reduces every axis and combines each element at its placement, after into where it is given: the contents it starts from, a term over its own domain; for a scan its fold, no axes, and scan: whether it runs from the last element down (reverse) and leaves each element out of its own prefix (exclusive), nothing for any other value; and for a value masked by formulas over its positions, masked: the formulas, each at most zero where the mask holds, and the number the value is where it fails (see Tempest.Compiler.IR.comparison_mask and Tempest.Compiler.IR.masked_result); observed: formulas over its positions, each at most zero where the program's results may depend on what it holds, nothing when they may depend on all of it (see Tempest.Compiler.observed); and for a recurrence's state, carried: the axis it steps along, the value it is carried from, a load over its domain read one step back, and whether it steps from the axis's last position to its first, reading one step on (reverse; see Tempest.Compiler.Carried).

Tempest.Compiler.Implement.own_domain — Function
own_domain(group, m) -> extents

The positions member m of a group covers: the group's domain, or, for a fold over fewer positions along axes it keeps, its own within the domain, as MLA's dV, over the values' 64 features, in the group of dK and dQ, over the 96 of the queries and keys. Such a fold's term is a term over the domain, but only at its own positions does it read within what it reads, and only there is it kept; nothing in the group reads it.

Tempest.Compiler.Implement.product_axes — Function
product_axes(group) -> (M, N, K, B) or nothing
product_axes(group, r) -> (M, N, K, B) or nothing

The axes of a group whose folds each sum a product of two factors over the group's primary axes K: those only the first factor reads (M), those only the second reads (N), and those both read and keep (B). Nothing when a fold is not such a product, or the folds split the axes differently; a fold of weights alone, a log-sum-exp beside attention's weighted sum, has no factors and rides the products' sweep. Given a fold r, the axes of that fold's product alone.

Tempest.Compiler.Implement.structure — Function
structure(group) -> Structure

All the view holds but reference, each value numbered by where it first appears: its members first, in order, then the values their placements and terms read, then those the values' own views name. Groups of one structure are one group but for their values' numbers, as a model's layers are: what an implementation answers of one (claims, variants, estimate) it answers of the others, where its claims name no value, and it may keep its answers by it (see Tempest.Compiler.SessionTable). Found once a view.

Tempest.Compiler.Implement.variants — Function
variants(implementation, target, group, claim) -> claims

The claims that vary claim, offered once it has measured best among the claims tried on group so far: the next stage of a search the implementation stages, as the generator stages its product tiles (every output tile at one depth, then the depths of the best and its split). Tempest.Compiler.Implement.Work — Type
Work(bytes; reread = 0, passed = 0, flops = 0, recomputed = 0, factor = Float32, blocks = Inf, split = false, applied = [], swept = [], inner = [], steps = 0, step_runs = [], stepped = [], refold_steps = 0)

One launch's work, which Tempest prices (see the manual's page A launch's work):

  • bytes: bytes moved;
  • reread: bytes it reads again, what its blocks read of an argument beyond the first time;
  • passed: bytes it passes to or takes from another of its claim's launches, partial results in a workspace, as a split sum's parts;
  • flops, factor: flops of products whose factors are of type factor;
  • recomputed: flops of folds it recomputes inside them;
  • blocks, split: its blocks, and whether they split the sums among them;
  • applied: the scalar functions it applies elementwise, each with the number of positions it is applied at;
  • swept: those applied inside a product's sweep, to its factors;
  • inner: those applied inside a fold the sweep recomputes, to that fold's tiles;
  • steps: the steps a block takes, where its blocks sweep tiles one after another, waiting for what each step loads before the next;
  • step_runs: what a block loads at a step: of each load, the bytes it reads in one run, contiguous, paired with the bytes it reads in the step;
  • stepped: the functions the steps compute on what they loaded, each with the number of steps it is applied in along their chain;
  • refold_steps: the steps apart in which a block recomputes a fold whose body is not bilinear along its axis.

A launch that states no steps, or one, is priced by its bytes, flops and functions alone.

Tempest.Compiler.Implement.resources — Function
resources(implementation, target) -> resources

What the launches implementation builds for one executable share, and nothing else uses: memory a launch writes only while it runs, as a library's workspace, made on target (allocate, upload) as the executable's buffers are. An executable runs one call at a time, its launches in order, so its launches may share it; another executable's, or a decider's timing claims beside it, have their own. Made once per executable, and once per decider for the claims it builds to time, when the first launch is built; nothing by default.

Tempest.Compiler.Implement.lowers — Function
lowers(implementation, target, term, group) -> Bool

Whether implementation can realize a group that applies term, an Apply in group, a GroupView: false for a generator without a lowering of the scalar function. Libraries

A library realizes the groups that compute a function Tempest can already compute. It names that function as a template, and Tempest finds the groups that compute it and hands the library each array as a strided view.

Tempest.Compiler.Implement.Library — Type

A library realizes the groups that compute one of its templates on a target: Tempest matches them and hands supports and build a Binding of the template's arrays. claims, estimate, build_claim, record_name and candidates are Tempest's for a library.

source
Tempest.Compiler.Implement.Template — Type
Template(f; inputs, outputs)

A function a library computes, f, of arrays named and with named axes in inputs, as (A = (:m, :k), B = (:k, :n)), returning the arrays named in outputs, one name for each, in order. Tempest traces f with arrays of the axes' extents; an axis no axis of a group matches has extent one. An axis stands for the group's axes that the same arrays read, the same folds sum and the same index formulas (a causal mask's) move with. Axes alike in all three are interchangeable, as attention's query positions and the query heads that share a key head are: the library is offered a binding for each way, those whose arrays are laid out as inputs names their axes first.

supports(library, target, binding) -> Bool

Whether library computes binding on target: the element types, extents and strides it takes; true by default. Tempest.Compiler.Implement.build — Function
build(library, target, binding, resources) -> (launch, description)

What build_claim is for a library: launch() computes the template into the binding's outputs from its inputs, each Strided with its buffer, on the task's stream, or every instance of bindings it supports, using the executable's resources (see resources), and description says what it runs.

Tempest.Compiler.Implement.Binding — Type

A group matched to the templateth of a library's templates: the extent of each of the template's axes in extents, and each of its inputs and outputs as a Strided view in arrays, by name.

Tempest.Compiler.Implement.Strided — Type

An array of a binding: elements of eltype at offset and the given strides, in elements, along axes of extents size. buffer is the storage it is a view of when the library builds, and nothing when it is asked whether it supports the binding.
