Tempest.Compiler.IR

Tempest.Compiler.IR — Module

The vocabulary the compiler's levels share and implementations read: index expressions over a domain, how values are laid out in storage, the algebra of folds, the terms of a kernel's body, and the masks index formulas state.

Folds

Tempest.Compiler.IR.Relative — Type
Relative(law, observe)

A fold relative to a statistic of its own elements, in one pass. An element is (y, g...), or a number y, which is (y, 1). The state is the statistic's state over the elements so far and one sum of g · φ(y - m) for each g, where m is the statistic and φ the law's function: for the Exponential law, exp(y - m) against the maximum; for the Square law, (y - m)^2 against the mean. Each sum is relative to the statistic of the elements it covers, and combining two states moves both to the statistic of their union by the law's rebase: exp turns a difference of maxima into a factor, and a sum of squares about a part's mean moves to the whole's by n (μ_part - μ)^2. So softmax and the variance are each one pass, with no statistic computed first. The result is observe(law, state).

logsumexp is the exponential fold of a number observed as m + log(sum) (LOGSUMEXP); the sums a softmax weighs, and the sums of squares about a mean, become relative folds by rewrite (see rewrite).

source
Tempest.Compiler.IR.Exponential — Type

exp(y - m) against the maximum m. A sum relative to one maximum moves to a larger one by the factor exp(m_old - m_new). Exponentials are shifted by zero when the maximum is infinite, so an empty or all -Inf slice sums to zero, and a +Inf element to +Inf.

source
Tempest.Compiler.IR.Square — Type

(y - m)^2 against the mean m, whose state is the count and the sum. A sum of squares about a part's mean moves to the mean of the whole by n_part (μ_part - μ)^2 (Welford's algorithm, as Chan combines it).

Tempest.Compiler.IR.Overwrite — Type
Overwrite()

The fold of a write: its state is the element it took last. A write by key starts each position from the array's contents there, so its initial state, zero, is never observed where a write has contents.

source
Tempest.Compiler.IR.fold_reduce — Function
fold_reduce(f) -> function or nothing

How to fold arrays of states along some of their axes at once, when f has a faster way than combining them in pairs: a function of the state's components, one array each, and the axes, that returns the folded components. Implementations call it on their own arrays, such as tiles. A relative fold takes the statistic first, so that each sum is moved once.

Tempest.Compiler.IR.reached_elements — Function
reached_elements(ts, dims, domain; run = 1)

The elements of a value of dims that loads ts of it reach over domain: along each axis, the span of the positions their indices take there, one where they are held, as a slice's index is, and no more than the positions each index visits, one for each point of the domain's axes it mentions, those an index it gathers through mentions among them: a table's rows gathered at 64 tokens are 64, wherever in the table they lie. Along the first axis, whose elements lie side by side, a position reached brings in run of them, the elements memory moves at once. Every element where an index mentions a variable past the domain's, as the body of a fold recomputed inside does.

Masks

Tempest.Compiler.IR.comparison_mask — Function
comparison_mask(f, a, b, domain) -> Vector{Affine}

The mask that the comparison f(a, b) of index formulas states: formulas, each at most zero where it holds. a <= b is a - b <= 0, a < b is a - b + 1 <= 0.

source
Tempest.Compiler.IR.held_formula — Function
held_formula(value, index, T, domain) -> Affine or nothing

The integer of type T that value holds at index, as a formula: a gather known to lie in the type's range, so that a position compared with it is a mask. Nothing for a type wider than 32 bits, whose range the arithmetic of formulas, in Int, could overflow.

source
Tempest.Compiler.IR.masked_result — Function
masked_result(f, T, args)

What f gives, as a T, where a mask fails, from its arguments there, each a number, :finite or nothing (unknown): a number when the numbers decide it, as a zero factor or an infinite summand does, in exact arithmetic; for a choice by a known condition, the branch it takes, whatever the other is; :finite for sums, products, quotients by a nonzero number and the functions here of finite arguments, which an overflow could make infinite, so that a program whose unmasked positions overflow computes a different nothing here.
