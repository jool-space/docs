Tempest.jl

Tempest compiles Julia array programs into fused GPU kernels. A whole training step, with the loss, its gradient and the optimizer, is traced once from plain Julia, planned into kernels, and replayed as one CUDA graph. Kernel packages such as cuTile and cuBLAS compete to run each part, and whatever no package claims still runs.

using Tempest, CUDACore, cuTile, cuBLAS

struct Dense{W, B}
    w::W
    b::B
end
(d::Dense)(x) = tanh.(d.w * x .+ d.b)
loss(m, x) = sum(abs2, m(x))

m = Dense(CuArray(randn(Float32, 64, 32)), CuArray(randn(Float32, 64)))
x = CuArray(randn(Float32, 32, 16))

grad = compile((m, x) -> Tempest.withgradient(loss, m, x), m, x)
l, (dm, dx) = grad(m, x)   # dm is a named tuple (w = ..., b = ...)
explain(grad)            # each kernel: what it computes and stores, and what runs it

Without a GPU, the same code runs on the CPU with plain arrays.

Loading

Tempest and its extensions compile their own code into package images as they precompile, so that a session compiles little of it again. Julia keeps ten images of a package (JULIA_MAX_NUM_PRECOMPILE_FILES), and each environment, each checkout of Tempest and each set of flags such as --check-bounds needs its own: past ten, the image evicted is compiled again, a minute or more, at its next using, so raise the cap where you keep several. precompile_workload = false under [Tempest] in an environment's LocalPreferences.toml skips the work Tempest and its extensions do while they precompile, for an environment whose Tempest changes often, at the cost of compiling that code in each session.

What holds

Tempest owns coverage and kernel packages own speed. A program written with Base's arrays and the primitives on the Tempest page runs with no kernel package loaded, on the kernels Tempest generates for itself, so loading a package or removing one changes how fast a program runs and never whether it runs. Each kind of change has one place: a new function is array code in the package that owns it, a new kernel is a change to a kernel package, and a better optimization is a change to Tempest.

What else holds is stated by the tests, not here. A property not yet met is a broken test under a name that says what would close it, and TRIALS.md in the repository is the docket of what the code is being measured against.
